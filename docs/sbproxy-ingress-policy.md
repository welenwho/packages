# 可选接入接口分流

位置：客户端设置 → 访问控制 → 接入接口分流。

默认关闭。即使开关打开，没有选择任何来源时也不增加 DNS 监听或防火墙规则。
无线和有线都支持多选、混合选择：

- “不接管的 WiFi”：按无线配置项选择，显示 SSID、radio 和 section；接口名变化自动跟随。
- “不接管的设备接口”：选择有线端口、网桥或其他接入设备。选中网桥会覆盖全部成员。
- 未选择的来源保持原来的监听范围和路由规则，不等于强制全代理。

例如 `who` 与 `who-5G` 同属 `br-lan`：保持监听 `br-lan`，只把 `who` 加入不接管列表。
前者绕过 SBProxy，后者继续执行现有分流。有线设备也可以同时选 `lan1`、`lan2`。
该功能不改变网桥成员、子网、DHCP 和普通局域网互访；不会替用户更改上级路由器的代理。

## 实现与边界

bridge prerouting 识别网桥成员，inet prerouting 同时支持网桥或独立三层接口。
临时包标记 `0x40000000` 只传递入口分类；在正常路由前转换为 sing-box 的 TUN
绕过标记（明确配置为 `0x2024`），或 TProxy 当前的 self_mark。不要在其他插件中复用此分类位。
不改写全局策略路由，也不修改 sing-box 自己的 nft 表。

选中来源的 TCP/UDP 53 查询会进入独立 DNS 入口：普通域名使用 WAN 直连 DNS，
本地域名、单标签主机名和反向解析交给 dnsmasq，Tailscale 优先 DNS 规则仍然保留。
DoH/DoT 作为普通业务流量绕过，不解密也不强制替换。选中的业务流量优先绕过，
不再匹配自适应、按域名代理或 MAC 强制代理规则。
本功能不放宽防火墙区域的输入权限：标准 LAN 区域可直接使用；如果接口属于拒绝访问
路由器服务的自定义区域，独立 DNS 入口也遵守该限制，不自动开放 WAN 上的 DNS 服务。

功能仅在代理客户端就绪时生效。规则采用独立 bridge/inet 表，提交前执行 nft 检查，
同一事务替换，生成失败保留上次规则；初次应用失败拒绝启动代理客户端，避免静默忽略策略。
运行期间每 5 秒跟踪 WiFi 设备名与表存在状态；停止、禁用或取消所有来源后清理专用规则。
内核依赖由包的 `kmod-nft-bridge` 自动提供，不要求用户手工装规则。

连接跟踪和 NSS/ECM/flow offload 可能让已有连接继续使用旧路径。配置改变后应重建连接，
必要时重新连接 WiFi。不会为应用策略而全局清空连接跟踪或关闭硬件加速，以免影响其他设备。
验证重点是新连接；不能承诺所有平台已有的硬件加速连接会即时改道。

## 验证

本地：`sh luci-app-sbproxy/tests/static-ingress-policy.sh`、
`python3 luci-app-sbproxy/tests/test-ingress-helper.py`。
OpenWrt：用 ucode 运行 `tests/ingress-policy.uc`，可传 `tun` 或 `tproxy` 输出测试规则供 `nft -c` 校验。
测试模块需与 `scripts/ingress.uc` 位于同一模块搜索目录。
